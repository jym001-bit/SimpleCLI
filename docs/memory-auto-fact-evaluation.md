# 自动事实提取评测（2026-09-24）

## 测试范围和评分方法

测试集在 `src/test/resources/memory/auto-fact-eval-v2.json`，共 18 条合成用户输入：10 条含稳定事实，8 条是不应保存的临时请求、问题、引用、代码或敏感信息。标准答案有 12 条原子事实，均为输入中的连续原文片段。每条输入使用独立的长期记忆目录，实际评分对象是最终写入的记忆，而非模型的原始回答。

一条写入的记忆若包含一条尚未匹配的标准事实片段，计一个真阳性；其余写入计误写入；未匹配的标准事实计漏提取。同一条写入最多匹配一条标准事实。报告精确率、召回率、F1、完全正确样例数和负例误写入数。预设通过门槛：F1 ≥ 0.85、至少 15/18 个样例完全正确、负例误写入为 0。

`AutoFactExtractionEvaluationTest` 提供两种运行：

```bash
# 固定响应：检验程序的筛选与写入，默认不调用真实模型
mvn -q -Dtest=AutoFactExtractionEvaluationTest -DskipTests=false test

# 真实模型：使用本机已配置的 GLM 凭证，发送合成输入
mvn -q -Dtest=AutoFactExtractionEvaluationTest -DskipTests=false \
  -Dpaicli.test.memory.live=true -Dpaicli.test.memory.provider=glm test
```

运行报告保存在 `target/memory-eval/`。凭证不会写入报告。真实模型测试默认关闭。

升级前的四个漏项来自确定性的程序门槛：礼貌用语被当作临时请求，部分仓库事实和未来回答习惯没有触发提取，混有凭证的消息被整条跳过。现在程序仅剔除含敏感信息的句子，同时保留其余安全句子；内联引用也不能直接作为用户事实写入。

v1 的“仓库的主语言是 Kotlin，构建工具是 Gradle”被标成单条事实；GLM 正确拆成了两条原子事实，初版评分因此把一次正确拆分同时记为漏提取和误写入。v2 把它标成两条事实，输入和 GLM 输出均未改变。复算没有新增模型调用。

GLM 实跑共 17 次模型调用，输入 2,722 token、输出 3,269 token。只有纯敏感信息样例在调用前被跳过。自动提取因此会为多数符合初筛条件的用户消息增加一次模型调用；这是当前实现的成本，需要在实际使用中继续观察。

本分数只代表这组小规模合成样例，不代表开放输入的准确率，也不覆盖真实对话中的长期效果、人工核实或不同模型的表现。
